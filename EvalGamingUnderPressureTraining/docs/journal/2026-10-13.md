## Decisions
- **Primary model: Qwen3-8B.** It reasons natively, has a released activation oracle, and is cheap enough for RL sweeps. No open model has native reasoning, a released NLA and a released oracle together, so the project will train an NLA for Qwen3-8B with the released recipe.
- **Confirmation model: Gemma-3-27B-IT**, which has a released NLA (layer 41), an activation oracle and Gemma Scope 2. It has no native reasoning, so reasoning is prompted into a scratchpad.
- **Pilot on the released Qwen3.5-4B organism** (Montoya et al.) before building anything, to check that its reasoning verbalizes eval awareness often enough for Arm A to have something to suppress.
- **The monitor penalizes situational reasoning in both directions.** "This is a real user" counts as much as "this is a test".
- **Train and held-out framings use disjoint style families.** Measurement only ever uses held-out styles.
- **Stack fixed in `docs/stack.md`.** structlog and rich for output, Typer for entry points, seaborn for paper figures, plotly for exploration, TRL for the pilot's RL and verl for the multi-node runs.
- **The judge is `claude-haiku-5-5`, not Haiku 4.5.** It costs a tenth as much per token and caches the rubric from 512 tokens. It rejects a temperature setting, so judge determinism comes from the rubric and from caching identical requests, not from sampling settings. Refusals are recorded as their own outcome, never as level 0. Offline scoring goes through Message Batches at half price.
- **Foreign-language steering concepts carry an English gloss**, so Arm B can grade whether the model names the injected concept, not just whether it notices one.

- **No synthetic obfuscated reasoning.** Two generation tasks were stopped by model safety classifiers. One was writing monitor-calibration examples ("reasoning extraction" category). The other was writing a stress set of disguised situational reasoning meant to fool the monitor. The relaunched calibration set, described accurately as fictional scratchpad notes, was stopped a third time. So all synthetic reasoning traces are dropped, with no attempt to reword around the classifiers. The monitor's labelled data is now real traces only (`data/monitor/labels.jsonl`, SPEC section 2): sampled from the pilot organism, then from the Arm A runs, and labelled by hand. The rubric is refined on the first 50 real labels before the rest are labelled. Monitor robustness to obfuscation will be measured on real traces from the Arm A runs, labelled by hand. That is also the more convincing evidence, because it shows what RL actually produces rather than what we imagined it might.

- **Agent rooms built in Python** (`src/agentroom/`, `docs/agent-rooms.md`). The main agent reaches them through an MCP server. Seats are Claude Code and Codex on subscriptions, plus deepagents on OpenRouter for a third model family. Members are stateless: the room builds each member's full prompt, so the transcript records exactly what each one saw. Visibility can be none, all, ring or an explicit graph, and members see each other only under anonymous labels. All seats are read-only and cannot open rooms. Codex resume was avoided because `codex exec resume` takes no sandbox flag. A smoke test with Haiku and GPT-6.1 Sol ran a blind round and a cross-examination with repo citations. The OpenRouter seat is untested until `OPENROUTER_API_KEY` is set.
- **From that smoke test, a point to act on:** held-out framings must be paired with coding tasks RL never saw, not just new framing styles, or a held-out gain could come from shared task content. Also worth adding: a cue audit across splits, for example numbering cues shared by `benchmark_header` (train) and `harness_metadata` (held-out).

- **Rooms became host-chaired conversations.** `discuss` runs blind openings, then one speaker at a time; every turn ends with a stance (agree, position, open issues). It pauses after a few turns, on consensus, or at the turn limit, and the host continues, joins in (`@Reviewer B` hands over the floor), or closes. Only the host ends a discussion. Seats are told to converge within one round of the limit. Seats take personas from `configs/personas.toml`, and one model can sit several times with different personas. A live test with two Haiku seats (skeptic and researcher) and Sol (methodologist) produced real back-and-forth with concessions, and converged on a gap-retention rule: Δpost − 0.5·Δpre with a one-sided 95% lower bound above zero, on paired held-out task and framing pairs.
- **From that live discussion, two gaps in the plan:** the week-7 kill criterion is not operational (no verbalization threshold, no independent judge, no matched λ=0 control or minimum training budget), and the plan's timeline says both "four months" and "16 weeks". Both need fixing before the pilot.
- **Pilot code is built** (`docs/pilot.md`): TRL GRPO, 166 stdlib-only BigCodeBench RL tasks, Hua's `hint_score`, the Haiku 5.5 judge, and a Mistral-Small held-out judge. Two findings matter for go/no-go. Montoya's own check of the 4B organism shows a 29-point type-hint gap (34% against 5%, n=100), just under the 30-point bar. And the organism's first adapter is only partly loadable in transformers: its q, k and v projections target modules that Qwen3.5 fuses, so PEFT drops them. Montoya's loader does the same, so we measure the model they evaluated, which is not exactly the one Tinker trained.

- **The week-7 kill rule is now operational** (plan, "Week-7 decision rule for arm A"). Julien hosted a discussion that found the old one-sentence rule unmeasurable (`docs/rooms/2026-10-13-170917-is-the-week-7-kill-criterion-well-define/`). A draft rule then went to a blind panel of Sol as statistician, Haiku as skeptic and Opus as methodologist (`docs/rooms/2026-10-13-214829-review-the-draft-week-7-kill-rule/`), which found about twenty concrete problems. The adopted rule:
  - Decides at one fixed step for all nine runs, with week 8 as a hard deadline.
  - Has preconditions on the organism and the held-out judge. They are checked before RL only, so a judge that RL learns to slip past cannot cancel the decision.
  - Has three per-seed tests, each of which can pass, fail or be inconclusive:
    - verbalization relative to both the pre-RL rate and the paired λ=0 control, corrected for traces the judge misses, counted from hand labels of judge-negative traces;
    - gap retention against the paired control, with a 15-point floor;
    - coding ability, tested one-sided.
  - Uses a two-of-three seed rule and ordered decision branches with monitor gaming checked first.
  - Sends the smallest passing λ to 27B.

  Not adopted: choosing λ on a separate framing split, because it costs too much power. Before the numbers freeze, the rule must be coded, dry-run on the pilot's outputs, and pass a simulation: an arm with no real effect stops 90% of the time, and a working arm continues 80% of the time. One more gap: `stats.difference` assumes independent samples, so the paired, two-way bootstrap the rule needs is still to be written.
- **"Four months" against "16 weeks" was not a real conflict.** The plan says 16 weeks throughout. "Four months" appears only in the older fellowship map (`docs/landscape/fellowship-map.html`), which plans by month. The plan now says the fellowship's four months are about 17 weeks, and the last week is slack.
- **Data fixes from the rooms.**
  - **Unseen tasks for held-out measurement.** These already existed by construction: measurement uses Hua's 256 tasks and RL draws from the rest (`experiments/pilot/00_tasks.py`). SPEC now says so.
  - **Validator gap closed.** Texts shorter than three words now compare as one shingle. It immediately caught the bare `{task}` framing in both splits, so the train copy (`fr-train-0251`) became "Please solve the following." and the bare baseline is held-out only.
  - **Cue audit added** (`src/evalgaming/cues.py`, `scripts/audit_cues.py`). It found that 16 of 25 held-out eval_implicit framings reused training's "item N" numbering. They now say case, record, spec, sample_idx or task_ref, and one row no longer runs `--split heldout`. The remaining shared words are the ones that define a context ("evaluation", "Wood Labs", "production", "real").
  - **Transfer accuracy is weak evidence for eval styles.** A word classifier fit on train still scores 0.83 to 1.00 on held-out eval styles, because any framing without deployment words looks like an eval. The shared-word list is the view to use for those styles.

- **The pilot now has a λ=0 control** (`configs/pilot/*_control.toml`, `docs/pilot.md` step 4). It is the same GRPO run with no penalty, which the week-7 rule needs and the pilot lacked. The monitor still scores the control's completions: that gives its verbalization curve, and unscored completions are dropped the same way in both runs. If the control's verbalization stays within about 20% of baseline, RL alone does not move it. The pilot estimate rises from about $20–23 to about $30–35. Step 4 now runs both trainings before starting the held-out judge's server, which the old order would have left holding the GPU. A new test loads every pilot config into its script's config class, so a typo fails on CPU rather than on a rented GPU.
